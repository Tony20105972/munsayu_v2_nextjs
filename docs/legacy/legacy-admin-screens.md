## 1. 레거시 기반 추정 — `INFERRED`

**판단:** 그누보드5 관리자 화면에 학원 전용 메뉴(설명회·강사·시간표·입학진단·문자신청·강사지원)를 추가한 구조로 보입니다.

**근거**
- 회원관리 안내 문구 "회원자료 삭제 시 다른 회원이 기존 회원아이디를 사용하지 못하도록 회원아이디, 이름, 닉네임은 삭제하지 않고 영구 보관합니다"는 그누보드5 기본 관리자 문구와 같음 (EV-ADM-02)
- 회원 목록 열 구성(본인확인 간편인증/휴대폰/아이핀, 메일인증, 정보공개, 광고성 이메일·SMS 수신, 성인인증, 접근차단, 권한, 접근그룹, 포인트)이 그누보드5와 같음 (EV-ADM-02)
- 접속자집계·접속자검색 메뉴와 탭 구성(접속자/도메인/브라우저/운영체제/접속기기/시간/요일/일/월/년)이 그누보드5와 같음 (EV-ADM-06, 07)

**이 추정이 맞다면 생기는 영향**
- 공개 주소가 그누보드 형식(`/bbs/...php`, `bo_table=` 게시판 등)일 수 있음 → Phase 1 경로 조사와 Phase 2 리다이렉트 설계에서 확인
- 그누보드5 DB 구조는 공개되어 있음 → 기존 DB 덤프를 받으면(D1) 데이터 이관 설계가 쉬워짐
- 관리자 경로(`/uAdmin/` — robots.txt 확인 EV-0002, `/adm/` 등)는 Phase 1에서도 접속 금지 유지

## 2. 화면별 관찰

### EV-ADM-01 로그인 화면
- 항목: 아이디, 비밀번호, 로그인 상태 유지(체크박스), 회원가입 버튼, 아이디 찾기, 비밀번호 찾기
- 관리자와 일반 회원이 같은 로그인 화면을 쓰는 것으로 보임 — `INFERRED`

### EV-ADM-02 회원관리
- 상단: 전체목록, 총회원수 **1명**, 차단 0명, 탈퇴 0명
- 검색: 검색 기준 선택(회원아이디 등) + 검색어
- 버튼: 선택수정, 선택삭제, 회원추가
- 목록 열: 아이디/이름/닉네임, 본인확인(간편인증·휴대폰·아이핀), 메일인증, 정보공개, 광고성 이메일 수신, 광고성 SMS/카카오톡 수신, 성인인증, 접근차단, 상태, 권한, 휴대폰, 전화번호, 최종접속, 가입일, 접근그룹, 포인트, 관리(수정·그룹)
- 등록 회원: 관리자 계정 1개 (이름 "문사유", 가입일 26-10-29, 포인트 900)
- **의미:** 공개 회원가입 기능은 있지만 실제로는 쓰이지 않음 → 신규 사이트에서 공개 회원 기능을 유지할지 결정 필요 (Q-ADM-01)

### EV-ADM-03 설명회관리
- 상단: 전체목록, 생성된 설명회수 **10개**
- 검색: 검색 기준(설명회 제목 등) + 검색어
- 버튼: 선택수정, 선택삭제, 설명회 추가
- 목록 열: 관리 코드, 상태(목록에서 바로 바꾸는 선택 상자), 설명회 제목, 개최일자/시간, 예약현황(n건, 링크), 참석인원(n명, 링크), 장소, 초청 연사, 등록일, 관리(수정)
- 관찰된 상태 값: `접수마감`, `마감임박` — 나머지 값(예: 접수중)은 `UNKNOWN`
- 관찰된 장소: 문사유 대치점, 문사유 분당점
- 관리 코드 형식이 제각각(`2026D5`, `2026b5`, `2026_bundang_5`, `26_11_04_14` 등) → 직원이 직접 입력하는 값으로 보임 — `INFERRED`
- 예약 건수와 참석 인원이 따로 집계됨(예: 24건 / 26명) → **예약 1건에 여러 명이 참석 가능** — `INFERRED`
- `UNKNOWN`: 정원 설정 여부, 상태가 자동으로 바뀌는지(정원·날짜 기준) 수동인지, 예약현황 클릭 시 나오는 예약자 목록의 항목

### EV-ADM-04 강사관리
- 제목: 문사유 강사 관리, 등록 강사 **28명**
- 필터: 전체보기, 대치팀, 분당팀, 컨설팅팀
- 버튼: 선택수정, 선택삭제, 새 강사 프로필 등록
- 목록 열: 노출순서(숫자 입력), 사진, 강사고유코드, 소속 분류 팀, 성명, 직책 및 주요 약력 요약, 관리(수정)
- **같은 강사가 팀마다 따로 등록됨** (예: 김윤환 원장 — `KYH` 대치팀, `KimYH` 분당팀) → 신규 설계에서 "강사 1명 : 소속팀 여러 개"로 바꿀지 결정 필요 (Q-ADM-04)

### EV-ADM-05 시간표관리 (강좌 시간표 관리)
- 지점 탭: 대치본원 시간표, 분당점 시간표 (화면은 대치본원, 등록된 시간표 **6개**)
- 버튼: 선택수정, 선택삭제, 새 시간표/강좌 추가
- 목록 열: 출력순서, 구분 섹션(예: 정규강좌), 학년 대분류 타이틀(예: 초등학교 4학년), 강사/평가명, 강좌/프로그램 타이틀, 강의시간/일정 메타(요일·시간, 개강일), **신청현황(n건, 링크)**, 관리(수정)
- **의미:** 설명회 외에 **강좌 수강 신청**도 받고 있음 → 공개 화면의 강좌 신청 폼 확인 필요 (Phase 1)
- `UNKNOWN`: 강좌별 정원, 신청현황 상세 항목, 신청 후 처리 방식

### EV-ADM-06 접속자집계 / EV-ADM-07 접속자검색
- 기간별 검색, 탭(접속자·도메인·브라우저·운영체제·접속기기·시간·요일·일·월·년)
- 목록 열: IP, 접속 경로, 브라우저, OS, 접속기기, 일시
- **관찰:** 기록된 IP가 모두 `172.31.x.x`(사설 IP), 브라우저·OS가 모두 "기타", 접속 경로가 비어 있음
- **의미:** 사이트 앞단의 로드밸런서·프록시 IP가 기록되고 있어 실제 방문자 정보가 거의 남지 않음 — `INFERRED`. `172.31.0.0/16`은 AWS 기본 VPC 대역이라 AWS에서 운영 중일 가능성이 높음 — `INFERRED` (D3·D7 참고)
- **제안:** 신규 사이트에서는 이 기능을 그대로 옮기지 않고 분석 도구(GA4, Vercel Analytics 등)로 대체 — 사용자 결정 필요 (Q-ADM-06)
