# 레거시 폼 계약 — Phase 1 관찰

> 모든 관찰은 GET·화면 열람만으로 수행했다. 입력, 동의 체크, 로그인, 가입, 제출은 수행하지 않았다.

## FM-001 강좌 수강 예약

- 등급: `OBSERVED` — `EV-0006`
- 진입: `/sub/schedule.n`의 **수강예약** 버튼. 대표로 대치본원 강좌 하나의 모달을 관찰했다.
- 화면상 선택 강좌 정보: 지점, 강좌명, 강의시간, 개강일.
- 필드: 학생 이름(placeholder `실명을 입력하세요`), 학부모 연락처(`010-0000-0000`), 재학 중인 초등학교명, 희망 수강 과정(초등 문해력·어휘·글쓰기·진단평가), 초등 학년(예비초~초6).
- 동의: 필수 체크박스. 목적은 좌석 배정 관리와 예약 확정 안내 문자 발송, 수집 항목은 이름·휴대폰 번호·학교/학년/수강과정, 보유기간은 해당 강좌 종강 및 정규 등록 안내 완료 시점 즉시 파기.
- DOM 계약: `method="POST"`, `action="javascript:void(0);"`; hidden `tt_id`(선택 강좌 ID), `campus`(대치본원), 필수 `rl_name`·`rl_hp`·`rl_school`, radio `department`·`grade`, 필수 동의 체크박스, submit. `EV-0008`
- 전송: `OBSERVED` — `submitReservation`은 `tt_id` 존재를 먼저 검사한 뒤 `$form.serialize()`를 `POST ./reserve_lecture_update.php`로 AJAX 전송하고 JSON 응답의 `success`/`message`를 처리한다. 전송 항목은 `tt_id`, `campus`, `rl_name`, `rl_hp`, `rl_school`, `department`, `grade`, 동의 체크박스다. `EV-0010`
- 제출 버튼: `수강 예약 신청서 제출하기`. 서버 검증·저장·실제 후속 상태는 `UNKNOWN` (제출 금지). 학부모 후속 연락은 직원 직접 처리로 신규 구현하지 않는다(사용자 답변 2026-11-09).
- 관리자 연결: `AD-008` 강좌 수강 신청 목록, `AD-013` 개인정보 보존·파기. `EV-ADM-05`의 시간표/신청현황과 연결된다.

## AD-011 강사 지원 (`/sub/Recruit`) — Phase 5 관찰

- 등급: `OBSERVED` — `EV-0014` (`docs/evidence/dom/phase5-recruit.yml`)
- 관찰 방법: GET 화면 열람만. 입력, 파일 선택, 제출은 하지 않았다.
- 진입: 주 메뉴에 없다. 주소를 직접 입력해야 들어간다. (새 사이트도 같다 — ASM-088)
- 필드: 강사명(실명), 연락처, 이메일 주소, 최종 학력, 논술 강의 총 경력 연수(선택 상자),
  강의 가능 전문 분과(복수 선택), 핵심 역량 지표(복수 선택), 한 줄 자기소개,
  주요 경력/합격 수치, 첨삭·리라이팅 노하우.
- 첨부: `이력서 및 자기소개서` **필수**, `교재·기출 해제안` 선택.
  화면 안내 문구는 `PDF·HWPM·DOCX만 허용`.
- 동의: 강사 채용·서류 심사용 개인정보 수집·이용 동의 **필수**.
- 제출 버튼: `문사유 아카데미 강사 지원서 제출하기`.
- `action`·`method`·서버 저장 방식은 `UNKNOWN` (제출 금지).
- 신규 구현 차이 (ADR-007):
  - 허용 형식을 **PDF·DOCX·HWP·HWPX** 로 두고 확장자가 아니라 **파일 내용**으로 확인한다. // ASM-085
  - 용량 상한 기본 10MB. 관리자 설정(`recruit.resume.maxBytes`)으로 바꾼다.
  - 제출 서류는 비공개 영역에 저장하고 공개 주소를 만들지 않는다. 관리자 인증 경로로만
    내려받고 내려받기마다 기록을 남긴다. (AD-013)
- 관리자 연결: `AD-011` 강사지원관리(`EV-ADM-09`), `AD-013` 개인정보 보존·파기.
