## 메일 업체 비교표

`phase-4-be-notes.md` 6장에 Resend·AWS SES·Postmark·Mailgun 4곳을 연동 난이도·무료 구간·한국 수신 도달률 참고사항·발신 도메인 인증 절차로 비교해 두었다. 가격·한도 숫자는 전부 `확인 필요`로 표시했다(인터넷 검색 없이 작성).

기술 관점 추천은 **Resend 유지**다. 어댑터가 이미 구현돼 있어 코드 변경이 0이고, 계정 찾기·비밀번호 재설정만 보내는 발송량에서는 단가 차이가 의미가 없다. 발송량이 늘거나 국내 도달률 문제가 실제로 생기면 AWS SES + 전용 IP로 옮기는 편이 유리하며, 교체 범위는 어댑터 파일 하나다.

## 통합(C-3)에서 찾아 고친 결함

1. **가입 Server Action이 세션을 만들지 않았다.** `openapi.yaml`과 `POST /api/auth/register`는 "가입 및 세션 생성"인데 화면 경로만 빠져 있었다. 세션 발급을 추가했다.
2. **비밀번호 재설정 메일 링크가 404였다.** 메일은 `/account/recovery/reset`을, 화면은 `/account/password-reset`을 쓰고 있었다. 메일 링크를 실제 경로로 고쳤다.
3. **회원 정보 수정 화면이 이메일·연락처를 비워 뒀다.** 세 항목을 함께 저장하는 폼이라 사용자가 다시 입력해야 했다. `getMemberProfile()`을 추가해 미리 채운다(`ASM-074` 해소).
4. **레거시 PHP 의존 검사가 주석과 canonical 도메인까지 위반으로 잡았다.** 주석을 걷어낸 뒤 `fetch`·`redirect`·`href/action`의 목적지만 보도록 고치고, `proxy.ts`의 `.php`가 출발지로만 쓰이는지 따로 검증한다.
5. **`server-only` 복원이 seed를 깨뜨렸다.** 그 패키지는 Next 번들러에만 있어 `tsx prisma/seed.ts`가 모듈을 찾지 못했다. `server-only`를 의존성으로 추가하고 seed 실행에 `--conditions=react-server`를 켰다. 클라이언트 번들 가드는 유지된다.

Phase 4 1차에서 BE가 스스로 찾은 결함도 있다: `getRetentionSetting()`이 `findUnique → create` 순서여서 신청 두 건이 동시에 들어오면 보존 설정 기본 행을 함께 만들려다 한쪽이 500을 내보냈다. 유일 제약 위반을 잡아 먼저 만들어진 행을 읽도록 고쳤다.

## 남은 UNKNOWN / 알려진 한계

- 자동 파기 스케줄러가 없다. 비밀값으로 보호한 실행 경로만 있고, 배포 환경(D3) 확정 후 스케줄러에 연결해야 한다.
- 요청 횟수 제한이 프로세스 내 메모리다(`ASM-022`). 인스턴스가 여러 개면 인스턴스별로 따로 센다. Phase 6에서 공용 저장소로 바꿔야 한다.
- 업로드는 구현하지 않았다(`ASM-008`, 이번 범위에 업로드 기능 없음).
- 동시 신청 부하 테스트는 Phase 6 범위다.
- `GET /api/admin/events/{id}/totals`는 없는 id에 404가 아니라 0 집계를 돌려준다(문서에 명시).

## 사용자 결정이 필요한 항목

1. **메일 업체 확정(D4 후속)** 과 요금제.
2. **munsayu.com DNS 권한(D7)** — SPF·DKIM 등록에 필요하다. 이것 없이는 실제 발송 검증을 할 수 없다.
3. 발신 주소(`MAIL_FROM`) 결정. 현재 기본값은 로컬 전용 가짜 주소다.
4. 배포 도메인 확정 — 메일 링크 기준 주소(`APP_BASE_URL`, `ASM-023`).
5. 설명회 신청 정보 보관 기간(`ASM-009`).
