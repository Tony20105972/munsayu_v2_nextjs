## 3. 알려진 한계

### 3-1. 스테이징은 세웠다 — 남은 빈틈은 **사람이 눌러 보는 점검**이다

2026-11-16 에 스테이징(`munsayu-v2-nextjs.vercel.app`, Vercel production 환경)을 세워
돌려 봤습니다. 전문은 `EV-0019`.

- **실제로 돌려 확인한 것**: 운영과 같은 환경의 마이그레이션·시드 · Blob 저장소에 사진
  올리기(공개 주소 200) · 예약 실행 경로의 인증 양방향(404/404/200) · 공개·관리자 경로
  점검 32건 · 되돌리기 8초/앞으로 14초.
- 거기서 **처음 드러난 결함 7건**을 고쳤습니다(보고서 8-2). 가장 큰 것은 **Blob 저장소
  하나로는 공개·비공개를 함께 담을 수 없다**는 것이었습니다 — 그대로 전환했으면 관리자가
  사진을 한 장도 올릴 수 없었습니다.
- **아직 돌려 보지 않은 것**: 신청 각 1건·상태 변경·CSV·공지 작성·휴대폰 화면(사람 몫) ·
  이력서 업로드 · Vercel Cron 이 스스로 부르는 실행 · 파기가 실제로 지우는 경로(스위치
  꺼짐) · 메일 발송(D4 미정) · **운영 DB 에서 표를 처음 만드는 장면**(운영 DB 는 전환
  당일 새로 만든다 — D10).

### 3-2. 옛 기록이 새 사이트에 없다 (D1, 되돌릴 수 없음)

- 옛 사이트의 신청·회원·공지 기록을 가져올 수 없습니다. DB 접근 권한이 없습니다.
- 전환 직전 진행 중인 신청은 **직원이 따로 보관**합니다 (`legacy-records-handling.md`).
- 공지 글은 공개 화면에서 읽을 수 있는 것만 가져오는 스크립트가 있습니다
  (`npm run import:notices`). 개인정보로 보이는 글은 건너뜁니다 (ASM-090).

### 3-3. 사진은 운영에서 다시 올려야 한다

- 사진은 데이터베이스가 아니라 파일 저장소에 있습니다. 스테이징과 운영이 저장소를 달리 쓰면
  운영에서 한 번 더 올려야 합니다 (`migration-checklist.md` 1-8).
- 코드에 들어 있는 레거시 사진 57개는 다시 올릴 필요가 없습니다.

### 3-4. 문자를 보내지 않는다 (D4, 의도된 것)

- 「문자신청내역」에 쌓이기만 하고 **자동으로 문자가 가지 않습니다.** 직원이 직접 연락합니다.
- 옛 사이트에도 자동 발송이 없었던 것으로 확인했습니다 (`INFERRED`, Q-ADM-11 답변).

### 3-5. 배포할 때마다 마이그레이션이 자동 실행된다

- `vercel.json` 의 빌드 명령이 `prisma migrate deploy` 를 먼저 돌립니다. 배포와 DB 구조가 어긋나지 않습니다.
- **Preview 배포는 건너뜁니다.** `VERCEL_ENV=production` 일 때만 적용합니다. 가드가 없으면
  아직 병합하지 않은 브랜치를 푸시하는 것만으로 운영 스키마가 바뀌고, 그건 배포 되돌리기로
  되돌아가지 않습니다. 실제 Preview 빌드 기록으로 건너뛰는 것을 확인했습니다(`OBSERVED`).
- 남은 걱정은 **구조가 아니라 데이터**입니다. 운영 DB 를 스테이징과 분리하지 않으면 가짜 시드와
  연습 중 지운 기록이 실제 기록과 섞입니다. → `migration-checklist.md` 1-7 에서 결정.

### 3-6. 감시 장치가 없다

- 사이트가 죽어도 **알림이 오지 않습니다.** 사람이 Vercel 화면을 열어 봐야 압니다.
- 신청 폼이 조용히 깨지면 몇 주 뒤에야 알게 됩니다.
- 선택지와 비용은 `docs/monitoring-plan.md`. **전환 전날 무료 가동 감시 하나는 붙이는 것을 권합니다.**

### 3-7. 작은 것들

- 레거시 폰트는 라이선스 확인 전이라 **시스템 글꼴로 대체**했습니다 (D6, ASM-041). 글자 모양이 다릅니다.
- 화면별 제목·설명(SEO)을 다르게 넣었습니다. 레거시는 전 화면이 같았습니다 → `Q-ADM-20`.
- 자체 접속자 집계는 만들지 않았습니다 (ASM-004). 외부 도구로 대체합니다.
- HEIC(아이폰) 사진 중 HEVC 방식은 변환하지 못하고 안내만 돌려줍니다 (ASM-091).
