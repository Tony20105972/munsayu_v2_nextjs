## 2. 성능 — 원인은 하나였다

측정해 보니 **홈이 가장 빨랐다.** 가장 무거운 화면이 가장 빠른 것은 이상해서 따라갔더니
모든 하위 화면의 LCP 가 같은 파일이었다.

상단 배너 `sub-hero.avif` 가 **1920x1280 · 267KB** 인데 CSS `background-image` 로 넣어
375px 휴대폰도 원본을 그대로 받고 있었다. 게다가 그 위에 **80~90% 불투명한 덮개**가
깔려 사진은 분위기만 낸다. 가장 안 보이는 것이 가장 무거웠다.

`next/image`(`fill`·`priority`·`sizes`) 로 바꾸고 AVIF 를 켜고 품질을 55 로 낮췄다.
**배너 267KB → 10KB.** 시각 회귀 104건이 기준 이미지를 그대로 통과해 보이는 모습이
달라지지 않았음을 확인했다.

Bootstrap·AOS·jQuery 는 애초에 이관하지 않았고, 웹폰트도 없으며(ASM-041), 관리자 목록에
N+1 도 없었다. 확인만 하고 보고서에 적었다.

## 3. 보안 — 차단 2건

### 보안 헤더가 하나도 없었다
`Content-Security-Policy`·`HSTS`·`nosniff`·`X-Frame-Options`·`Referrer-Policy`·
`Permissions-Policy` 가 전부 없었고 `X-Powered-By: Next.js` 가 나가고 있었다.
`proxy.ts` 에서 요청마다 nonce 를 만들어 붙이도록 했다. matcher 를 전 경로로 넓혔지만
레거시 주소 처리가 **먼저** 끝나 RT-001/002/004 동작은 그대로다(308·410 확인).
E2E 52건이 CSP 를 켠 채 전부 통과했다.

### CSV 내보내기에 건수 상한이 없었다
내보내기 4개가 모두 조건에 맞는 **모든 줄**을 메모리에 올렸다. 필터 없이 한 번 누르면
개인정보가 담긴 표 전체가 한 파일로 나간다. 조용히 자르면 「현재 필터 결과 전체」라는
약속(ASM-006)이 거짓이 되므로, 2만 줄을 넘으면 **거절하고 범위를 좁히라고 알려 준다.** // ASM-097

### 권장 2건
- 관리자 경로 50개에 「만료된 세션 → 401」 테스트 추가. 코드는 맞았지만 확인하는 테스트가 없었다
- `sitemap.xml` 의 제외 기준을 `robots.txt` 차단 목록과 같게 맞췄다

## 4. Gate 판정

기준 원본은 `docs/MIGRATION_PLAN.md` 6장이다.

| # | 기준 | 판정 | 근거 |
|---|---|---|---|
| 1 | 주요 화면 모바일 Core Web Vitals 양호 (LCP ≤ 2.5s · CLS ≤ 0.1 · INP ≤ 200ms) | **통과** | 7개 화면 전부 LCP 600~636ms · CLS 0.000 · TBT 6~24ms. 아래 단서 참고 |
| 2 | 보안 점검에서 차단 등급 이슈 0건 | **통과** | 차단 2건을 찾아 **모두 고쳤다.** 고친 뒤 0건 |
| 3 | 스테이징 부하 테스트에서 신청 API 오류율 기준 충족 | **방법 대체** | 아래 설명 |

**판정: 2개 충족 / 1개는 방법을 바꿔 수행.**

### 1번의 단서 — INP 를 직접 재지 못했다
INP 는 실제 사람의 조작이 있어야 나오는 값이라 합성 측정으로는 얻을 수 없다. Lighthouse 와
같은 방식으로 **TBT(긴 작업 50ms 초과분의 합)** 를 대용값으로 썼다. 측정값 5~36ms 는
기준(200ms)의 20% 미만이라 여유가 크지만, **실제 INP 는 운영에서 사용자 자료로 확인해야 한다.**

### 3번을 글자 그대로 채우지 못한 이유
기준은 「**스테이징** 부하 테스트」인데 스테이징은 Phase 7 에서 만든다. 사용자 지시도
「로컬 실행만」이었다. 또 「기준은 Phase 2 에서 정함」이라고 되어 있으나 **Phase 2 문서에
구체적인 오류율 기준이 없다.** 그래서 「5xx 0건」을 기준으로 삼아 측정했고 결과는 0건이다.
스테이징이 서면 같은 스크립트를 `LOAD_TEST_BASE` 로 가리켜 다시 돌린다.

> Gate 기준 자체를 바꾸는 것은 사람 결정이라 여기서는 사실만 적는다.

## 4-1. 독립 리뷰 (차단 3 / 권장 6 / 참고 5)

차단 3건을 모두 고쳤다. 가장 중요한 것은 **CSP 가 운영에서 실제로는 전부 막혔다**는
지적이었다. 개발 서버로만 확인하고 「통과」라고 적었는데, 운영 빌드에서 직접 보니
화면당 11~13건씩 모두 62건이 막혔다. nonce 를 버리고 다시 확인해 **0건**으로 만들었다.
상세는 `phase-6-review.md`.
