## 차단 3건 — 모두 수정

### R1. CSP 검증 근거가 틀렸다 — 실제로는 운영에서 전부 막혔다

보고서에 「E2E 52건이 CSP 를 켠 채 통과」라고 적었지만, E2E 는 **개발 서버**를 본다.
개발 CSP 에는 `'unsafe-eval'` 이 더 있고 미리 만든 HTML 을 그대로 내려주지도 않는다.
운영 CSP 를 검증한 근거가 아니었다.

리뷰 지적대로 운영 빌드에서 직접 확인했더니 **화면당 11~13건씩 모두 62건이 막혔다.**
`'strict-dynamic'` 이 있으면 CSP3 브라우저가 `'self'` 를 무시하는데, `cacheComponents`
로 미리 만든 HTML 의 스크립트에는 요청별 nonce 를 넣을 수 없기 때문이다.

**수정:** nonce 를 버리고 `script-src 'self' 'unsafe-inline'` 으로 갔다. 한계는
`security-report.md` 에 분명히 적었다. 운영 빌드 5개 화면에서 **위반 0건·수화 정상** 확인.

### R2. 계약 문서를 고치지 않았다

내보내기 4개가 새로 **409** 를 돌려주는데 `openapi.yaml` 에 없었다. 계약을 바꾸면 문서를
먼저 고쳐야 한다(CLAUDE.md 5장).

**수정:** 내보내기 4경로에 409 응답과 ASM-097 설명 추가, `migration-matrix.md` AD-013
검증 칸에 상한 기재. (사람 승인 대상으로 보고서에 올린다)

### R3. 새 규칙(ASM-097)에 테스트가 0건이었다

**수정:** 상한을 주입할 수 있게 `takeForExport(read, max)` 로 바꾸고 단위 테스트 5건 추가 —
상한 미만 통과 / **경계값(=상한) 통과** / 상한+1 거절 / 문구에 실제 건수·개인정보 없음 /
읽는 양이 상한+1 로 묶임.
