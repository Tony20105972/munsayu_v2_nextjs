# 되돌리기 계획 (전환 실패 시)

> Phase 7에서 작성. 전환 중에는 이 문서를 **열어 둔 상태로** 작업합니다.
> 관련: `docs/migration-checklist.md` · `docs/legacy-records-handling.md`

---

## 1. 되돌리기는 두 종류다

| 종류 | 무엇을 되돌리는가 | 걸리는 시간 | 신청 기록 |
|---|---|---|---|
| **A. 배포만 되돌리기** | 새 사이트의 **앞 버전**으로 돌아간다. 주소는 그대로 새 사이트 | **10초대** (스테이징 실측 — 3-1) | 그대로 남는다 |
| **B. 옛 사이트로 되돌리기** | DNS 를 옛 서버로 돌린다. 학부모는 다시 옛 사이트를 본다 | 5~15분 (TTL 300초일 때) | 새 사이트 DB 에 남아 있지만 **아무도 못 본다** → 4장 |

**먼저 A 를 시도합니다.** A 로 해결되지 않는 문제(새 사이트 전체가 안 열림, 신청이 전혀 안 됨)만 B 로 갑니다.

---

## 2. 되돌리는 조건 (판단 기준)

### 2-1. 바로 B (옛 사이트로) — 하나라도 해당하면 즉시

- [ ] 공개 화면이 **열리지 않는다** (500, 흰 화면, 인증서 오류)
- [ ] 신청 폼이 **전혀** 저장되지 않는다 (5건 시도 중 5건 실패)
- [ ] 개인정보가 **엉뚱한 사람에게 보인다** (다른 신청자 정보가 화면에 나온다)
- [ ] 관리자 로그인이 안 되고 30분 안에 원인을 못 찾는다
- [ ] **학원 메일 수신이 끊겼다** (MX 를 잘못 건드린 경우) → DNS 를 즉시 원복

### 2-2. 먼저 A (앞 버전으로) — 30분 안에 고쳐지면 계속

- [ ] 한두 화면만 깨졌다
- [ ] 사진이 안 보인다 (`STORAGE_ADAPTER` 설정 문제일 가능성이 높다)
- [ ] 글자·문구가 틀렸다
- [ ] 관리자 화면 한 메뉴만 오류
- [ ] 비밀번호 재설정 메일이 안 간다 (메일 설정 문제. 급하지 않다)

### 2-3. 되돌리지 않는 경우

- 레이아웃이 옛 사이트와 조금 다르다 → 의도된 변경이다 (`docs/reports/legacy-parity-report.md`)
- 검색 결과에 아직 옛 주소가 보인다 → 며칠~몇 주 걸린다. 정상이다
- 신청이 평소보다 조금 적다 → 하루는 지켜본다

### 2-4. 판단 시각

- 전환 **+2시간**에 원장님이 "계속 / 되돌리기" 를 정합니다. 애매하면 **되돌립니다.**
- 그날 **저녁 6시**까지 안정되지 않으면 되돌립니다. 밤새 깨진 사이트를 두지 않습니다.

## 3. 되돌리는 절차

### 3-1. A. 배포만 되돌리기 (1~3분) — `개발`

1. Vercel → 프로젝트 `munsayu-v2-nextjs` → **Deployments**
2. 전환 전에 잘 돌던 배포를 찾는다 (전환 당일 배포보다 **하나 앞**)
3. 그 배포의 `⋯` → **Instant Rollback** (또는 Promote to Production)
4. 1분 뒤 `https://munsayu.com` 을 새로 고쳐 확인한다
5. 확인 항목: 홈이 열린다 / 강좌 신청 1건이 저장된다 / 관리자 로그인된다

> **주의 — 마이그레이션은 되돌아가지 않습니다.** 배포를 되돌려도 데이터베이스 구조는
> 새 버전 그대로입니다. 보통은 문제가 없지만(컬럼이 늘어난 경우), 컬럼을 **지우거나 이름을
> 바꾼** 마이그레이션이 섞여 있으면 앞 버전 코드가 깨집니다. 그때는 A 로 해결되지 않으므로
> B 로 갑니다. 지금까지의 마이그레이션에는 그런 변경이 없습니다 (`prisma/migrations` 확인).

### 3-1-1. 스테이징에서 **한 번 실제로 해 봤습니다** (2026-11-16, EV-0019 3-4)

| 단계 | 명령 | 걸린 시간 |
|---|---|---|
| 앞 버전으로 | `npx vercel rollback <앞 배포 주소> --yes` | 명령 4초, 주소에 반영 **8초** |
| 앞으로(되돌리기 취소) | `npx vercel promote <새 배포 주소> --yes` | **14초** |

되돌린 상태에서 **앞 버전 코드가 새 스키마에서 그대로 돌았습니다** — 홈·공지·설명회·
예약확인·관리자 로그인 200, 옛 주소 308, `/uAdmin` 410, 가져온 공지 2건 보임.
앞 버전에 없는 경로(`/api/cron/privacy-purge`)만 404 였습니다(정상).

> 화면(Instant Rollback) 대신 **명령**으로 했습니다. 전환 당일에는 둘 중 손이 빠른 쪽을
> 쓰면 됩니다. 명령을 쓰려면 미리 `npx vercel login`·`npx vercel link` 가 되어 있어야 합니다.

### 3-2. B. 옛 사이트로 되돌리기 (5~15분) — `도메인관리자`·`개발`

1. **`도메인관리자`** DNS 에서 munsayu.com 의 A / CNAME 레코드를 **전환 전 값**으로 되돌린다
   - 전환 전 값은 `migration-checklist.md` 1-3 에 적어 둔 값이다
   - 적어 두지 않았으면: 옛 호스팅 업체 관리 화면의 서버 IP 를 확인한다
   - **MX·TXT(SPF) 는 건드리지 않는다**
2. **`개발`** Vercel 에서 커스텀 도메인 `munsayu.com`·`www.munsayu.com` 을 **지운다**
   (지우지 않으면 인증서 갱신 오류 메일이 계속 온다)
3. **`직원`** 옛 사이트 신청 폼을 **다시 연다** (`migration-checklist.md` 1-2 의 반대 작업)
4. 5~15분 기다린 뒤 다른 네트워크(휴대폰 LTE)에서 `munsayu.com` 이 옛 사이트인지 확인한다
5. **`직원`** 공지사항(옛 사이트)에 "홈페이지 단장을 잠시 미룹니다" 글을 올린다
6. **`개발`** 4장의 신청 처리를 한다

### 3-3. 되돌린 뒤 할 일 — `개발`

- [ ] 무엇이 왜 깨졌는지 한 쪽으로 적는다 (`docs/reports/phase-7-report.md` 에 덧붙인다)
- [ ] Vercel 의 Runtime Errors / Logs 를 **되돌리기 전에** 복사해 둔다 (지나면 보기 어렵다)
- [ ] 새 사이트는 **로그인 보호를 다시 켠다** (임시 주소가 공개로 남지 않게).
      스테이징에서 이 보호가 **꺼진 채 공개로 열려 있었던** 적이 있다 — production 별칭은
      기본 설정에서 보호 대상이 아닐 수 있다. `ssoProtection` 을 `all` 로 둔다 (EV-0019 3-5)
- [ ] 다음 전환 날짜를 다시 정한다

## 4. 전환 중에 새 사이트로 들어온 신청 처리

전환 작업 중과 되돌리기 사이에는 **새 사이트로 신청이 들어올 수 있습니다.**
되돌리면 그 신청은 새 사이트 데이터베이스에 남아 있지만 학부모도 직원도 보지 못합니다. **잃지 않게 합니다.**

### 4-1. 되돌리기 직후 (30분 안에) — `개발`·`직원`

1. **`개발`** 새 사이트의 임시 주소(`munsayu-v2-nextjs-....vercel.app`)로 관리자 로그인한다
   - 로그인 보호를 다시 켜면 Vercel 계정으로 먼저 들어가야 한다
2. 전환 시각 이후에 들어온 신청을 **메뉴별로 전부 확인**한다
   - 강좌 신청 / 설명회 예약 / 설명회 알림 신청 / 진단 상담 / 강사 지원
3. 각 목록을 **CSV 로 내려받는다**
4. **`직원`** 내려받은 분들께 **전화로** 연락한다
   - "홈페이지 작업 중에 신청이 들어와 확인이 늦었습니다. 접수된 것으로 처리해 드리겠습니다."
   - 새 사이트에서 **다시 신청하라고 하지 않는다.** 이미 받은 신청이다
5. **`직원`** 옛 관리자 화면(또는 학원 접수 대장)에 손으로 옮겨 적는다
6. CSV 파일은 옮겨 적기가 끝나면 **지운다** (`legacy-records-handling.md` 2-2 와 같은 규칙)

### 4-2. 건수가 0건이면

- 아무 일도 하지 않습니다. 확인했다는 사실만 적어 둡니다.
- 전환을 **평일 오전**에 하면 대개 0~2건입니다.

### 4-3. 다시 전환할 때

- 새 사이트 데이터베이스에 남은 그 신청들은 **지웁니다.** 4-1 에서 이미 옛 대장으로 옮겼기 때문에,
  남겨 두면 같은 분에게 두 번 연락합니다.
- 지우는 것은 관리자 화면에서 건별로 합니다. `npm run db:reset` 은 **쓰지 않습니다**
  (운영 데이터베이스를 비웁니다).
