# ADR-010 — 관리자 비밀번호 바꾸기·초기화 (AD-016)

- 상태: 확정
- 날짜: 2026-11-16
- 결정한 사람: 사용자 (2026-11-16 지시)
- 관련 근거: D5(단일 관리자 역할), D4(메일 업체 미정), ASM-014(argon2id), `scripts/bootstrap-admin.ts`
- 관련 ADR: ADR-005(인증·비밀번호 해시), ADR-007(Phase 5 관리자 범위 변경), ADR-009(전환 준비)

## 배경

관리자 화면에는 **비밀번호를 바꾸는 자리가 없었다.** 회원 쪽에는 있었지만
(`/account/profile`), 그 Action 은 **회원 세션 쿠키만** 보기 때문에 관리자가 쓸 수 없다.

그 상태로 전환하면 이렇게 된다.

- `bootstrap:admin` 이 만든 **임시 비밀번호가 운영 관리자의 영구 비밀번호**가 된다.
  그 값은 터미널에 찍혀 사람 손을 거쳐 전달된다(또는 명령 줄에 적힌다).
- 비밀번호를 잊은 직원을 풀어 줄 길이 없다. 메일 재설정 경로(FM-003)는 메일 업체가
  정해지기 전까지 **동작하지 않는다**(D4). 유일한 길은 개발자가 DB 를 직접 고치는 것이다.

레거시 관리자 메뉴에는 없던 기능이라 관찰 근거로 정당화할 수 없다. ADR-008(AD-015)과
같은 방식으로 **새 기능 ID(AD-016)** 를 붙여 범위 변경을 드러낸다.

## 결정

### 1. 본인 변경 — 「내 계정」(`/admin/account`)

현재 비밀번호 확인 → 새 비밀번호 2번. 계약은 회원과 같은 `changePasswordSchema` 를 쓴다
(영문+숫자, 10자 이상). 서비스(`changePassword`)도 회원과 **같은 것**을 쓴다. 관리자용
사본을 만들지 않는다 — 비밀번호 규칙이 두 곳으로 갈리면 한쪽만 고치는 사고가 난다.

### 2. 다른 관리자 초기화 — 「회원 관리」(`/admin/members`)

- **새 비밀번호를 받지 않는다.** 서버가 임시 비밀번호를 만들어 **한 번만** 돌려주고
  저장하지 않는다. 누르는 사람이 값을 고르면 그 값이 폼·기록·화면에 남고, 사람이 고른
  값은 대개 약하다.
- 화면이 한 번 보여 주고 버린다. 다시 볼 길은 없고 잃어버리면 다시 초기화한다.
- **메일로 보내지 않는다.** 지금은 메일이 안 되고(D4), 된 뒤에도 비밀번호는 메일로
  보내지 않는다.
- **자기 계정은 403 으로 막는다.** 지금 쓰는 세션이 끊기면서 임시 비밀번호만 남아
  혼란스럽다. 자기 비밀번호는 1번으로 바꾼다.
- 관리자가 아닌 계정은 404. 회원 비밀번호는 이 화면에서 다루지 않는다.

### 3. 바꾸거나 초기화하면 **그 계정의 모든 세션을 끊는다**

비밀번호를 바꾸는 이유가 「누가 내 계정으로 들어왔을지도 모른다」일 수 있다. 남은 세션을
살려 두면 바꾼 의미가 없다. 지금 쓰는 창까지 끊기므로 다시 로그인하게 만든다.

### 4. 임시 비밀번호로 들어온 계정은 **변경 전까지 아무 일도 못 한다**

`User.mustChangePassword` 열을 더한다. `bootstrap:admin` 과 초기화가 그 깃발을 켜고,
본인이 비밀번호를 바꾸면 꺼진다.

막는 자리를 **두 겹**으로 둔다.

| 겹 | 어디 | 무엇을 막는가 |
|---|---|---|
| 화면 | `app/admin/(authed)/layout.tsx` | 모든 관리자 경로가 이 레이아웃 아래에 있다. 깃발이 켜져 있으면 `children` 대신 변경 폼만 보여 준다. 메뉴도 감춘다 |
| 권한 | `requireAdminFromCookies` · `requireAdmin` | Server Action 과 Route Handler 를 직접 부르는 길. 403 으로 막는다 |

화면만 막는 것은 권한 처리가 아니다(`CLAUDE.md` 4장). 그래서 권한 확인 자리에서도 막고,
**비밀번호를 바꾸는 Action 하나만** `allowPasswordChangePending` 으로 지나간다. 그 예외가
없으면 계정이 영구히 잠긴다.

### 5. 감사 기록

`PASSWORD_CHANGE`(본인) · `ADMIN_PASSWORD_RESET`(초기화)을 더한다. **값은 남기지 않는다** —
누가 언제 누구에게 했는지만 남긴다 (AD-013, `CLAUDE.md` 4장).

실패(현재 비밀번호 틀림)는 **기록하지 않는다.** 남기면 틀린 시도로 기록이 가득 차고,
로그인 실패 제한(`LoginAttempt`)이 이미 그 자리를 맡고 있다.

## 고려했지만 하지 않은 것

- **메일 재설정 경로를 관리자에게도 연다** — D4 가 정해지기 전까지 동작하지 않는다.
  정해진 뒤에 다시 본다.
- **「회원 관리」에서 만든 관리자 계정도 변경을 강제한다** — 이번 지시 범위 밖이라
  하지 않았다. 다만 그 계정도 비밀번호를 만든 사람이 알고 있다는 점은 같다.
  → 다음에 볼 거리로 남긴다(`createAdminAccount` 에 같은 깃발을 켜면 된다).
- **임시 비밀번호에 유효 기간을 둔다** — 지금은 없다. 계정이 잠기는 쪽이 더 큰 사고라고
  봤다. 초기화한 사실이 기록에 남으므로 오래 방치된 것은 기록으로 찾을 수 있다.

## 한계

- 임시 비밀번호는 **사람이 전달한다.** 전화·대면을 전제한다. 그 경로의 안전은 코드가
  보장하지 못한다.
- 강제 변경은 **관리자 세션에만** 적용된다. 회원 계정에는 이 깃발을 쓰지 않는다.
