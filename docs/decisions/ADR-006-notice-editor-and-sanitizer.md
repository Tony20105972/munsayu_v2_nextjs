# ADR-006 — 공지 본문 편집기와 HTML 정리기 선택

- 상태: 확정
- 날짜: 2026-11-12
- 관련: AD-014 공지사항 관리, 사용자 지시 2026-11-12 (3항 "편집기 라이브러리 선택은 ADR로 남긴다")
- 근거: EV-ADM-10 / EV-ADM-11 (레거시 게시판 1개), EV-0007 (공지 목록·상세 공개 화면)

## 무엇을 정했나

1. **HTML 정리기(sanitizer)는 `sanitize-html` 라이브러리를 쓴다.** 직접 만들지 않는다.
2. **편집기는 새 라이브러리를 넣지 않고 `contenteditable` 기반 최소 편집기를 직접 만든다.**

## 왜

### 정리기를 라이브러리로 쓰는 이유

본문 HTML 정리는 보안 경계다. 손으로 만든 정리기는 아래 같은 우회를 놓치기 쉽다.

- 주석·CDATA·조건부 주석 안에 숨긴 태그
- 속성값 안의 `javascript:` · `data:` 주소, 개체 참조로 쪼갠 스킴
- `<svg>`·`<math>` 안의 외래 콘텐츠 파싱 규칙 차이
- 태그를 닫지 않아 파서가 구조를 다시 세우는 경우

`sanitize-html` 은 널리 쓰이고 유지되는 허용 목록 방식 정리기다. 의존성 1개를 더 넣는 비용보다
XSS 를 직접 막아야 하는 위험이 크다. (CLAUDE.md 6장 — 새 의존성은 이유를 적는다)

정리는 **저장 전에 서버에서** 한다. 화면에서 거르는 것에 기대지 않는다. 설정은
`src/server/lib/sanitize-notice-html.ts` 한 곳에만 둔다.

### 편집기를 직접 만드는 이유

- 레거시 공지는 글 2건, 게시판 1개다(EV-0007, EV-ADM-10). 필요한 서식은 굵게·기울임·목록·링크·
  제목·이미지 정도다.
- TipTap·Lexical·Quill 같은 편집기는 번들이 수백 KB다. 관리자 화면 한 곳에서만 쓰기에 무겁다.
- 어떤 편집기를 쓰든 **서버에서 다시 정리한다.** 편집기가 만든 HTML 을 믿지 않으므로,
  편집기 선택이 보안 수준을 좌우하지 않는다.
- 이미지 업로드는 Server Action(`uploadNoticeImageAction`)으로 처리하고 돌려받은 주소를 본문에 넣는다.

## 바꾸는 방법

표·각주·버전 기록처럼 손으로 만들기 어려운 기능이 필요해지면 TipTap 으로 바꾼다.
그때도 서버 정리기(`sanitizeNoticeHtml`)는 그대로 두고 편집기 컴포넌트만 교체한다.

## 결과

- 새 의존성: `sanitize-html` + `@types/sanitize-html` (개발 의존성)
- 허용 태그·속성 목록: `src/server/lib/sanitize-notice-html.ts`
- SVG 는 본문 이미지로 받지 않는다. 스크립트를 담을 수 있다. (`detectImageFormat`)
