# ADR-005 — 인증 설계와 비밀번호 해시 방식

- 상태: 채택 (Phase 4)
- 날짜: 2026-11-11
- 관련: `ASM-014`, `ASM-002`, BLUEPRINT 7장, `docs/contracts/openapi.yaml`
- 영향 파일: `src/server/auth/**`, `prisma/schema.prisma`(`User`, `AuthSession`, `PasswordResetToken`, `LoginAttempt`)

## 배경

Phase 4에서 공개 회원(FM-003)과 관리자(AD-001) 인증을 직접 구현한다. 레거시는 그누보드5 기반으로
추정되지만 내부 소스와 DB를 볼 수 없어 기존 해시 형식을 이어받을 수 없다. 기존 데이터도 이관하지
않기로 했으므로(D1) 해시 방식을 새로 고를 수 있다.

Phase 4 초기 스켈레톤은 Node 내장 `scrypt`를 직접 조합해 쓰고 있었다. 직접 조합한 코드는
salt 길이·반복 계수·형식 문자열을 모두 손으로 관리해야 하고, 뒤에서 매개변수를 올릴 때
기존 해시와 섞이는 문제를 스스로 처리해야 한다.

## 결정

1. **비밀번호 해시는 argon2id를 쓴다.** 저장소에 이미 `argon2` 패키지가 있고, 매개변수는
   OWASP 권고값(`memoryCost=19456KiB`, `timeCost=2`, `parallelism=1`)으로 고정한다.
   해시 문자열에 알고리즘과 매개변수가 함께 들어가므로 나중에 매개변수를 올려도 기존 해시를
   계속 검증할 수 있다. 구현은 `src/server/auth/password.ts` 한 곳에만 둔다.
2. **회원 세션과 관리자 세션을 완전히 분리한다.** 쿠키 이름을 `munsayu_member_session` /
   `munsayu_admin_session`으로 나누고, `AuthSession.scope`(`MEMBER` / `ADMIN`)를 저장한다.
   `requireAdmin()`은 관리자 쿠키만 받아들이므로 회원 쿠키로는 관리자 요청이 통과할 수 없다.
   회원 세션만 있는 요청은 403, 아무 세션도 없으면 401로 구분한다.
3. **세션 토큰은 32바이트 난수이고 DB에는 SHA-256 해시만 저장한다.** 쿠키는 `HttpOnly`,
   `SameSite=Lax`, `Path=/`이고 `NODE_ENV=production`에서만 `Secure`를 붙인다.
   `rememberMe`가 켜지면 30일 `Max-Age`를 주고, 꺼지면 브라우저 세션 쿠키로 두고 서버 만료는 1일이다.
4. **쿠키는 `next/headers`가 아니라 요청·응답 헤더로 직접 다룬다.** 서비스 계층은 HTTP를 모르고,
   Route Handler가 `Request`의 `cookie` 헤더를 읽고 응답에 `Set-Cookie`를 붙인다.
   표준 `Request`/`Response`만 쓰므로 통합 테스트가 핸들러를 그대로 호출해 검증할 수 있다.
5. **로그인 시도 제한은 DB(`LoginAttempt`)에 기록한다.** 서버가 재시작해도 유지된다.
   식별자(아이디)는 원문으로 저장하지 않고 `AUTH_SECRET`을 pepper로 섞은 SHA-256 해시만 남긴다.
   기준값은 공유 계약의 `LOGIN_ATTEMPT_LIMIT`(5회 / 10분 / 15분 잠금)을 쓴다.
6. **비밀번호 재설정 토큰도 해시만 저장한다.** 1회용이고 `PASSWORD_RESET_TOKEN_TTL_MINUTES`(30분)
   뒤 만료된다. 성공하면 `usedAt`을 남기고 해당 사용자의 모든 세션을 지운다.
7. **계정 존재 여부를 응답으로 알려 주지 않는다.** 아이디 찾기와 비밀번호 재설정 요청은
   계정이 있든 없든 같은 202 응답을 주고 결과는 메일로만 보낸다.
   `BLOCKED`·`WITHDRAWN` 계정은 로그인할 수 없고, 실패 사유도 구분해서 알려 주지 않는다.

## 대안과 버린 이유

| 대안                                         | 버린 이유                                                                                                   |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Node 내장 `scrypt` 직접 조합 (기존 스켈레톤) | salt·형식·매개변수 상향을 직접 관리해야 하고 검증 로직에서 길이 비교 실수가 나기 쉽다                       |
| bcrypt                                       | 72바이트 입력 제한이 있고 메모리 비용을 조절할 수 없다. 새 의존성을 더 넣어야 한다                          |
| 쿠키 하나에 역할을 넣어 공용 세션으로 쓰기   | 역할 판정 실수 한 번이 권한 상승으로 이어진다. 쿠키·세션 범위를 나누면 실수해도 관리자 경로가 열리지 않는다 |
| 외부 인증 서비스(예: OAuth, 관리형 Auth)     | 운영자 요구에 없고 신규 외부 의존과 비용이 생긴다. 회원 기능 범위가 작아 과하다                             |
| 메모리 기반 로그인 시도 제한                 | 재시작·다중 인스턴스에서 카운터가 사라져 제한이 사실상 없어진다                                             |

## 결과

- 비밀번호는 `$argon2id$...` 형식으로만 저장된다. 다른 형식의 해시는 검증 실패로 다룬다.
- bcrypt 등으로 바꿔야 하면 `src/server/auth/password.ts`의 두 함수만 교체하고,
  다음 로그인 성공 시 재해시하는 절차를 추가한다. 다른 코드는 바뀌지 않는다.
- 관리자 API는 매 요청 `requireAdmin()`을 호출한다. 전 경로에 대해 비로그인 401·회원 세션 403을
  확인하는 통합 테스트가 `tests/integration/ad-001-admin-auth.test.ts`에 있다.
